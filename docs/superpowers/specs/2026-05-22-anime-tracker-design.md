# 日漫追番网站 — 设计文档（修订版）

## 概述

面向动漫爱好者的公开社区网站，提供当季新番追踪、多维度排行、讨论社区和影片导航功能。

**目标用户**：公开社区，面向所有动漫爱好者

**技术栈**：Next.js 全栈 + Python 爬虫服务 + PostgreSQL

---

## 页面结构

```
首页

│   ├─ 季度选择器（2026春 / 2026夏 / 2026秋 / 2027冬 ...）
│   ├─ 周历视图 ↔ 网格视图切换

```

```
│                Next.js 全栈应用               │
│  ┌──────────┐ ┌──────────┐ ┌─────────────┐ │
│  │ 追番日历  │ │ 新番排行  │ │  百家小坛    │ │
│  └────┬─────┘ └────┬─────┘ └──────┬──────┘ │
│  ┌────┴─────┐ ┌────┴─────┐              │  │
│  │ 新番影院  │ │ 我的追番  │              │  │
│  └──────────┘ └──────────┘              │  │
│                API Routes                     │
│          ┌──────┴──────┐                     │
│          │  PostgreSQL  │                     │
│          └─────────────┘                     │
└─────────────────────────────────────────────┘
                    ▲
                    │ REST API
                    ▼
┌─────────────────────────────────────────────┐
│           Python 爬虫服务 (独立进程)          │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────────┐  │
│  │ B站  │ │抖音  │ │Bangumi│ │ 豆瓣     │  │
│  └──────┘ └──────┘ └──────┘ └──────────┘  │
│  每12小时抓取 → 写入 PostgreSQL               │
└─────────────────────────────────────────────┘
```

### 数据流

- **爬虫层**：Python 定时任务（每12小时），抓取各平台数据和角色元数据，清洗归一化后写入 PostgreSQL
- **计算层**：Next.js API Routes 读取原始数据，按权重公式计算各榜单排名
- **展示层**：Next.js 页面 SSR 渲染，客户端水合后交互
- **用户层**：站内观看/评分/追番标记写入数据库，参与播放量榜、追更率榜、评分榜计算

### 技术选型

| 层 | 技术 | 原因 |
|----|------|------|
| 前端 | Next.js (App Router) | SSR对SEO友好，公开社区需要搜索引擎收录 |
| 后端API | Next.js API Routes | 与前端同仓库 |
| 数据库 | PostgreSQL | 排行聚合查询能力强，支持JSON字段存储爬虫原始数据 |
| ORM | Prisma | 类型安全，迁移管理方便 |
| 认证 | NextAuth.js | 支持邮箱/GitHub/Google多方式登录 |
| 爬虫 | Python (httpx + BeautifulSoup) | Python爬虫生态成熟，独立进程避免阻塞主站 |
| 定时任务 | Python APScheduler | 满足12小时间隔需求 |

## 模块一：追番日历

### 功能

当季新番的导航中心，展示本季度所有TV动画和动画电影。用户点击卡片进入对应番剧的新番影院（详情页）。

### 布局

- **默认周历视图**：按周一至周日排列，每天播出哪些番一目了然
- **可切换到网格卡片墙**：所有新番以卡片展示，按热度或评分排序
- **TV / 电影分Tab**：TV用周历，电影用卡片列表（电影无"每周更新"概念）
- **季度选择器**：顶部可切换季度（2026春 → 2026夏 → 2026秋 → 2027冬），默认当前季度。往季可查看历史新番

### 每个新番卡片信息

- 封面图
- 番剧名称（中日双语）
- 播出时间（周几 / 具体时间）
- 当前更新到第几集
- 综合评分（来自评分榜）
- 播放来源标签（有站内源 / 仅外部链接）

### 点击行为

- 卡片点击 → 进入新番影院（番剧详情页）
- 不在卡片上直接放播放按钮，统一在详情页完成播放、讨论、评分的操作

### 数据来源

- 当季新番元数据：Bangumi / 豆瓣 / B站番剧索引
- 播出时间表：各平台节目表汇总
- 角色列表：从 Bangumi 番剧页面下的角色列表爬取（角色名、日文名、CV）

## 模块二：新番影院（番剧详情页）

### 定位

番剧详情页，追番日历卡片的落地页，用户的核心操作枢纽。

### 页面内容

**基本信息区：**
- 封面大图
- 番剧名称（中日双语）
- 剧情简介
- CV表 / 制作公司 / 监督等信息
- 角色列表（含角色名、声优、头像）

**播放源区：**
- 站内嵌入播放（iframe 嵌入外部合规播放源）
- 外部播放链接列表（B站、巴哈姆特等正版平台直达链接）
- 优先展示站内可播放源，无站内源的显示外部链接
- 不存储任何视频文件

**评分组件（一次提交完成）：**
- 5星评分（可打半星 0.5 ~ 5.0）
- 星级自动映射推荐：4-5星 = "推荐"，3星 = "一般"，1-2星 = "不推荐"
- 分类标签（可选填）：神作 / 佳作 / 还行 / 劣作 等
- 星级分布图（可视化展示社区评分分布）
- 推荐率（"XX%的用户推荐"）

**操作按钮：**
- 追番（加入追番列表）
- 标记当前看到第几集
- 进入百家小坛（该番讨论吧）

### 观看进度自动追踪

- 用户在新番影院点击某一集播放时，**自动记录**为"已看第N集"
- 同时保留手动标记入口（下拉选择集数）
- 追更率计算优先使用自动数据

### 跳转逻辑

1. 站内有播放源 → 站内iframe嵌入播放
2. 站内无播放源 → 列出外部正版平台跳转链接

## 模块三：新番排行

### 五个榜单

#### 1. 热度榜

衡量社区讨论和二创活跃度。

| 维度 | 权重 | 数据来源 |
|------|------|----------|
| B站社区 | 40% | 以番剧名+片名为关键词搜索近7天UGC稿件，综合播放/点赞/投币/收藏/弹幕/评论/转发计算 |
| 抖音话题 | 22% | 番剧话题播放量 + 近7天新增视频数 |
| Bangumi讨论 | 20% | 条目讨论帖数 + 评论数 |
| 豆瓣讨论 | 18% | 短评数 + 讨论帖数 |

#### 2. 评分榜

衡量番剧质量口碑。

| 维度 | 权重 | 说明 |
|------|------|------|
| Bangumi评分 | 55% | 核心二次元用户群，评分最严格专业 |
| 豆瓣评分 | 20% | 用户基数大，修正Bangumi小众偏好 |
| B站评分 | 10% | 评分普遍偏高，作参考项 |
| 站内评分 | 15% | 百家小坛/新番影院用户评分，初期低，随用户量上调 |

异常处理：评分人数不足50人的番剧，自动降低Bangumi权重，提高豆瓣权重修正小样本偏差。

#### 3. 播放量榜

衡量实际观看和追番规模。

| 维度 | 权重 | 说明 |
|------|------|------|
| 站内观看 | 40% | 新番影院各集播放数 + 用户"追番"数 |
| B站播放量 | 30% | 有版权取各集播放量之和，无版权为0 |
| Bangumi在看 | 18% | 标记"在看"人数 |
| 豆瓣在看 | 12% | 标记"在看"人数 |

容错逻辑：B站无版权时，站内权重临时提升至55%，Bangumi提至28%，豆瓣提至17%。

#### 4. 追更率榜

衡量番剧留住观众的能力。纯站内数据，**数据来自播放页自动追踪**。

```
追更率 = (自动记录"看过最新集"人数 ÷ 自动记录"看过第1集"人数) × 100%
```

- 门槛：看过第1集人数 < 50 的番剧不上榜

#### 5. 角色人气榜

衡量角色在社区中的热度和讨论度。

| 维度 | 权重 | 数据来源 |
|------|------|----------|
| B站应援稿件 | 50% | 以角色名（译名/日文原名/全名）搜索，统计稿件综合互动数据 |
| 抖音角色话题 | 25% | 角色名相关话题播放量 |
| Bangumi讨论 | 15% | 角色名在讨论帖中被提及的频率 |
| 豆瓣提及 | 10% | 短评/讨论中角色名被提及的频率 |

角色名匹配规则：覆盖译名、日文原名、全名、部分全名；排除社区爱称、片中角色称呼的外号等非正式名称。

角色元数据来源：每季度初从 Bangumi 番剧角色页面爬取（角色名、日文名、CV），角色热度数据按12小时频率更新。

### 榜单页面的公共功能

- 清晰展示排名数据（得分、各维度明细）
- 条目点击 → 跳转到对应新番影院
- 每个榜单独立Tab切换
- 数据来源标注 + 更新时间分开显示：
  - 外部数据（B站/Bangumi/豆瓣/抖音）：标注具体刷新时间，每12小时
  - 站内数据（本站播放/评分）：准实时，几分钟内生效

## 模块四：百家小坛

### 结构

- **每个新番一个独立"吧"**（讨论区），类似百度贴吧
- 从新番影院页点击"百家小坛"按钮进入对应吧

### 帖子系统

- **纯文字内容**：发帖和回帖仅支持文字，不支持图片/视频/附件上传
- **自由发帖**，默认不强制选分区
- **系统自动标签**：根据内容关键词自动打标签（剧情讨论、情报搬运、二创分享、资源交流、评分吐槽等）
- **首页双Tab**："最新回复"和"热门帖子"

### 内容审核（后期补充）

- **智能屏蔽词系统**：敏感词库 + 正则匹配，发帖/回帖时自动过滤
- 支持自定义词库扩展
- 可配置审核策略（直接拦截 / 替换为*** / 人工审核后放行）
- 此项为后期功能，初期不做

### 用户行为

- 发帖 / 回帖 / 引用回复
- 所有评分行为统一在新番影院完成（百家小坛内不再设独立评分入口，和影院共用一套评分数据）

## 模块五：我的追番（新增）

### 功能

用户个人追番管理中心。

### 页面内容

- **追番列表**：已标记"追番"的番剧，按本周播出时间排列
- **观看进度概览**：每部番显示"已看N集 / 共M集"
- **今日更新高亮**：当天有更新的番自动标亮，提醒观看
- **我的评分历史**：我打过的所有评分一览，可修改评分
- **今日要看的番**：按播出时间排序的今日待看列表

## 实体关系概览

```
Anime (番剧)
  ├─ id, title, title_jp, cover, synopsis
  ├─ season, year, broadcast_day, broadcast_time
  ├─ episode_count, current_episode
  ├─ studio, director, cv_list (JSONB)
  └─ created_at, updated_at

AnimeRanking (排名数据 - 每次爬取后更新)
  ├─ anime_id
  ├─ heat_score, score_score, view_score, retention_score
  ├─ raw_data (JSONB - 各平台原始数据)
  └─ calculated_at

Character (角色)
  ├─ id, anime_id
  ├─ name, name_jp, cv, avatar
  ├─ aliases (JSONB)
  └─ character_score

User (用户)
  ├─ id, username, email, avatar
  └─ created_at

UserFollow (追番)
  ├─ id, user_id, anime_id
  └─ created_at

UserWatchProgress (观看进度 - 自动追踪)
  ├─ id, user_id, anime_id
  ├─ current_episode, status (watching/completed/dropped)
  ├─ is_auto (是否为自动追踪)
  └─ updated_at

UserRating (用户评分 - 在新番影院提交)
  ├─ id, anime_id, user_id
  ├─ rating (0.5~5.0), tags (JSONB, 可选), recommend (自动映射)
  └─ created_at

ForumPost (吧内帖子)
  ├─ id, anime_id, user_id
  ├─ title, content, auto_tags (JSONB)
  └─ created_at, updated_at

ForumReply (回帖)
  ├─ id, post_id, user_id, content
  └─ created_at

PlaySource (播放源)
  ├─ id, anime_id
  ├─ source_name, url, type (iframe/redirect)
  └─ is_available
```

## 非功能性要求

- **性能**：榜单页面ISR缓存1小时；番剧详情页SSR渲染
- **安全**：NextAuth.js CSRF保护；API Routes输入验证；防SQL注入（Prisma参数化查询）
- **扩展性**：爬虫独立进程，未来可拆分到独立服务器
- **SEO**：番剧详情页SSR渲染，OG标签，站点地图自动生成
